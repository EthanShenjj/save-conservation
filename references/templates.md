# Save Conversation Templates

Use these templates when writing raw memory documents or final reports.

## New Raw Document

```markdown
---
date: YYYY-MM-DD
platform: Codex
topic: 对话主题
scope: general 或 项目名称
tags: [标签1, 标签2]
---

# 对话：{主题描述}

## 对话概要
{2-3 句话说明这次对话的背景、目的和结果}

## 用户意图
{用户为什么发起这次对话？想解决什么问题？}

## 对话内容

### Q1: {用户问题/需求}

{AI 的关键回答摘要，保留核心逻辑和关键信息，不要逐字搬运但也不要遗漏重要细节}

### Q2: {用户追问}

{AI 的回答摘要}

## AI 的关键行动
- {具体做了什么，如：创建了文件、设计了架构、给出了建议}
- {每个行动的结果}

## 关键产出
- {对话中产出的文件路径、配置、代码等}
- {重要的决策或结论}

## 用户反馈
{用户对 AI 回答的反应：满意、修正、补充？TA 说了什么？}
```

## Same-Day Increment

```markdown
---

## 增量更新：HH:mm - {本轮主题}

### 本轮概要
{1-2 句话说明这次增量更新补充了什么}

### 新增对话内容
{按 Q/A 摘要本轮新增内容}

### 新增关键行动
- {本轮新增行动}

### 新增关键产出
- {本轮新增文件、决策或结论}
```

## 完整对话原文

当用户明确要求完整保留对话时，在常规元数据和可选摘要之后使用以下结构；按发生顺序写入所有可获得内容，不得压缩或改写。

```markdown
## 完整对话原文

### 用户

{用户消息原文}

### 助手

{助手回复原文}

### 工具调用

{工具名称与输入原文}

### 工具结果

{工具输出、错误与相关文件路径原文}

### 用户

{后续用户消息原文}
```

## Save Report

```markdown
## 对话已保存

**存储分类**：`general` 或 `{项目名称}`
**raw 记录**：`raw/general/YYYY-MM-DD-简短描述.md` 或 `raw/{项目名称}/YYYY-MM-DD-简短描述.md`
**来源摘要**：`wiki/sources/YYYY-MM-DD-简短描述.md`

### 新增/更新页面
- 实体：[列出新增或更新的实体页]
- 概念：[列出新增或更新的概念页]
- 洞察：[列出新增的洞察页]

### 持久化记忆
- [列出新创建的 memory 文件，如无则写“无”]
```
